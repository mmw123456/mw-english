# v0.9.0 导入词表（PDF / Word）

一件新事：以前「我的词表」只能一个一个手工加，现在可以把现成的 PDF、Word 词表整个导进来。

## 1. 入口

词库页右上角一颗导入按钮（上传图标），点进整页「导入词表」。**只有这一个入口**：不占 Tab、不上首页。

## 2. 能导什么

| 格式 | 说明 |
|---|---|
| `.pdf` | 主路。直接调 pdfium 抽文本，全程本地 |
| `.docx` | 主路。解 zip 读正文，段落与表格都认 |
| `.txt` / `.csv` | 退路。UTF-8（认 BOM）；不是 UTF-8 会明说，不猜编码 |
| 粘贴文本 | 退路。把词表直接粘进来，一行一个词 |

老版 `.doc` 不做 —— 选到会明说「请用 Word 另存为 .docx 再导」，不会硬解析出乱词。

## 3. 解析规则

一行一条，认这些排版：

- 编号列表：`1. abandon`、`2、prompt`、`(3) immune`、`[4] violate`、`- deliberate`
- 一行一词：`abandon`
- 词 + 词性 + 释义：`transmit v. 传播；播送`
- 逗号 / 分号 / 全角逗号：`abandon, 放弃`
- Tab 分隔：`abandon → 放弃`
- **短语整串保留**：`take advantage of`、`once (and) for all` 不会被拆成几个词

种子 PDF 那种「词独占一行、释义另起一行、再跨一行」的排版也接得住：

```
3 prompt
v. 导致，敦促；鼓励…说下
去； adj. 迅速的，及时…
```

三行合成一个词 `prompt`，释义接成 `v. 导致，敦促；鼓励…说下去； adj. 迅速的，及时…`。不接的话 `v.` 会被当成一个词导进去。

表头、标题、页码、空行整行跳过，不算「没认出来」；**认不出来的行会原样列出来**，不静默丢。

## 4. 先预览，确认才写库

选完文件先进预览页，不直接入库：

- 顶部一行摘要：`解析出 42 个词 · 重复跳过 3 · 文件内重复 1 · 2 行没认出来`
- 每行一颗复选框 + 词 + 释义；点行能改词与释义，「不要这个」直接删掉这条
- 右上角「全选 / 全不选」一键切
- 底部按钮写明确数字：**「导入 40 个新词」**，点了才写库；一个都没选时按钮是灰的

解析中显示「正在解析 7 / 20 页」，每页之间让出一次事件循环，20 页的 PDF 也不会把界面卡住。

## 5. 导进去的词怎么算

导入的词**就是自加词**，走 v0.8.0 定好的那套，不另立规矩：

- 进同一套六箱，从 0 箱起步，占每日新词配额
- 820 排在前面，导入的词按添加顺序排（先导的先学）
- 去重大小写不敏感（`Abandon` 与 `abandon` 算同一个），已在 820 或已在自加词里的跳过，摘要里报出跳过数
- 释义口径：**文件里自带的 > 内置词典补 > 都没有就标「未查到」**。不编释义、不联网、不调 AI
- 记来源：每批导入记文件名与导入时间，方便溯源
- 从词表移除导入词时按 v0.8.0 规则清学习记录，热力图历史保留

## 6. 失败与边界

- 文件打不开 / 空文件 / 一个词都没解析出来：一句人话报错，不崩、不半导入（写库在单个事务里）
- `.doc`、非 UTF-8 的 txt、不是 zip 的 docx、损坏的 PDF，各有各的提示
- **全程本地**：release 清单里没有 `INTERNET` 权限，文件不上传

## 没动的地方

Leitner 的降箱 / 熟词保护 / 连续答对门槛、断档三档规则、每日目标范围、设置页三项、斩词、shader 与玻璃常量、Tab 栏与左右划切页、热力图、箱色表、字重与颜色体系、首页任务卡与色带 —— 全部零改动。

## 装哪个

- `app-arm64-v8a-release.apk` — 绝大多数手机，选这个（versionCode **2026**）
- `app-armeabi-v7a-release.apk` — 老的 32 位机（versionCode **1026**）
- `app-x86_64-release.apk` — 模拟器（versionCode **4026**）

`versionName 0.9.0`，minSdk 24，targetSdk 36。三份 APK 的 versionCode 不同是 Flutter 分包自动加的 `1000 × ABI 码`（arm64 +2000、v7a +1000、x86_64 +4000），不是 bug，也不许强制统一。
